# LoreCue 前端体验样机

这是 LoreCue 的可点击前端体验样机，包含创作工作台、“我的团”、主持人咨询台、场次档案、资料库和全局 AI 助手。
当前用于验证信息组织、操作流程与视觉效果，不连接数据库或真实 AI。

## 可以体验什么

- 小说、影视剧本、跑团模组与世界观项目首页
- 按创作类型建立新项目，并自动获得相应的章节、场次、线索或条目结构
- 项目、内容创作、故事结构、设定资料、视觉媒体、检查管理六个分级领域
- 正文、大纲、故事树、故事节点、二维图、双层时间线与版本快照
- 角色档案中的动机、人物弧、说话方式、知情范围与披露条件
- 人物关系图、地点地图、组织阵营、物件线索与世界观设定
- 跑团模组专属的主持人真相、场景节点、线索网络、NPC 知情、地图遭遇、结局和玩家手册
- 文档树全文搜索、新建文档、章节正文编辑与浏览器自动保存
- 文档复制、跨分组移动、可撤销归档和归档内容筛选
- 整个创作项目可导出带格式版本与项目身份的 JSON 备份
- 备份导入会校验大小、格式、版本和项目身份，先预览再确认，并可撤销最近一次导入
- Markdown 快捷工具、专注写作、阅读预览、页面宽度与字数统计
- 文内查找替换、草稿状态、叙述视角、地点和故事时间元数据
- 单篇 Markdown 导出，便于在浏览器草稿之外留存副本
- AI 修改先显示原文与建议差异，由作者明确接受或保留原文
- 右侧写作检查栏可从 Markdown 标题生成大纲，并分别查看检查、引用和私有备注
- 检查结果标明检测方式、正文依据和设定依据，不把相似性判断冒充事实
- 项目级一致性工作台区分规则冲突、文本相似和 AI 语义候选，并可并排查看双侧原文
- 检查结论可标为确认、忽略或待核实，但不会自动改写正文、设定卡或团历史
- 一致性与疑似重复提醒
- 人物关系、线索触点和故事发生顺序与叙述顺序对照
- 从项目已引用资料中插入地图、立绘或 BGM 引用
- 比较与恢复历史版本，恢复前先保护当前内容
- 手动项目快照会持久保存完整文档集，可比较文档数量、总字数和具体变更文档
- 恢复快照需要二次确认，并会先自动建立“恢复前保护”快照
- 文档、快照、导入撤销点与 AI 咨询统一进入按项目 ID 隔离的 LoreCue Project Store v1
- 创作项目目录同样会在当前浏览器持久保存，新建项目刷新后仍可继续打开
- 首次打开会无损迁移旧版浏览器草稿；旧键不会被删除，无法识别的统一数据会先进入隔离副本
- 多个 D&D、CoC、CoJ、无限团项目的首页、筛选和搜索
- 新建团时也可选择系统无关或自定义规则
- 区分规则系统、剧本模板、实际团项目与场次档案
- 同一个剧本模板可以建立互不串线的不同团项目
- 新建团项目草稿并分别填写剧本模板与团名
- 团项目目录会在当前浏览器持久保存，刷新后仍按规则、模板和实际团名分层
- 五种情况：明确答案、合理推断、临场新编、泄密风险、团后确认
- 三种咨询强度：严格依据、最小补全、救场优先
- 区分“原文明确”“合理推断”“暂无依据”
- 区分“原文摘录”“AI 拟词”“AI 新编”
- 把复制与实际采用分开
- 将实际说出或发生的临场内容送入团后归档台
- 手动 BGM 建议，不监听对话，也不自动切歌
- 场次列表、团前简报、本场目标和使用资料快照
- 按时间记录剧本事实、玩家行动、主持人陈述与临场新编
- 团后逐条决定口胡是长期事实、NPC 主张、仅本场还是废弃
- 场次列表、团前简报、本场目标、下一次团草稿和口胡复盘状态统一写入对应团项目的 Campaign Store v1
- 团后状态变化会同步更新团项目卡片的待复盘数量，不会改动其他团或原始剧本模板
- 为下一次团保留承接信息
- 统一管理人物、地点、地图、立绘、BGM、规则和文档
- 可从本机导入图片、音频、PDF 与文本资料；元数据保存在 Asset Catalog v1，真实二进制文件单独保存在浏览器 IndexedDB
- 每条资料保存原始归属、玩家可见范围、剧透说明、素材来源和文件状态，单文件暂限 100 MB
- 创作项目与团项目分别建立资料引用；取消引用不会删除原文件，也不会影响其他项目
- 正文“插入素材”只列出当前创作项目明确引用的资料，并写入带稳定素材 ID 的可追溯标记
- BGM 与角色立绘工作台会读取当前项目的资料仓引用和源文件状态，不会自动借用其他项目素材
- 地图层级与地图遭遇只能绑定当前创作项目明确引用的地图，并按节点或遭遇保存稳定素材 ID
- 玩家手册只提供非“主持人私有”的项目素材作为公开来源，避免误把主持人原件带入玩家材料
- 玩家手册和玩家附件发放前必须选择实际团项目与场次，并同时保存团、场次、接收者、版本和素材 ID；同一模组的不同玩家组不会串线
- 场次档案会按当前团项目和场次汇总实际发放资料，包括已撤回但玩家曾经看到的版本，供团后复盘与 AI 知识边界使用
- 主持人咨询台的 AI 上下文可显式纳入本场玩家实际收到的资料；已撤回内容仍算玩家已知，但不会因此反向赋予 NPC 同样的知识
- 采用 AI 咨询草稿时会冻结当时的团、场次、现场输入与玩家资料披露快照，后续撤回资料也不会改写当时依据
- 场次档案会按团与场次汇总 AI 咨询留痕，可查看问题、建议、现场输入和当时知识边界，并单独标记为已复盘而不升级设定
- 团后复盘把临场事实与 AI 咨询纳入统一待处理总数，但分别执行“事实归档”和“咨询已复盘”，避免把复盘动作误当成设定确认
- 下一场承接清单只从已确认事实、NPC 主张、未决问题和保留状态生成带来源候选；主持人勾选后才写入下一场草稿，AI 咨询不会直接入选
- 玩家附件把主持人原件、玩家版本和实际发放历史分开；每次发放保留素材 ID、接收者、场次与版本，撤回也不会抹除历史
- 资料详情会反向列出地图节点、遭遇和玩家资料中的使用位置；取消项目引用前先提示断链，历史发放永不随绑定删除
- 工作台会明确标记已取消项目引用的失效绑定，可重新绑定或单独解除，而不会静默改用同名素材
- 资料只有被项目明确引用后才进入对应 AI 检索范围
- AI 助手提供查设定、创作协作、冲突检查与 GM 救场入口
- 每次咨询先勾选当前条目、角色档案、当前场次或项目设定库，也可手动粘贴玩家原话与现场状态
- 可指定主持人或 NPC 回答视角，并在生成前预览“允许知道”与“禁止越界”的知识边界
- AI 回答同时展示原文依据、合理推断和 AI 新编，不会自动写回正文或设定
- 复制建议与采用草稿分开；采用时仍需二次确认，AI 新编只会进入待确认区
- 采用后的咨询按项目保存在当前浏览器，可标记为已复盘，但不会因此升级成正式设定

## 原型边界

首页包含多个演示创作与团项目，创作深度交互集中在“潮汐来信”，带团深度交互集中在
“萨菲港旧案 · 老友组”。正文、项目、场次与资料元数据会保存在当前浏览器的数据仓中；从本机导入的
素材文件会写入同一站点的 IndexedDB，但不会复制到仓库目录、上传服务器或同步其他设备。AI 回答仍为演示数据，不会调用真实模型。更换浏览器、清理站点数据或
更换设备后，浏览器草稿不会自动迁移。
它不接入语音、QQ 群聊或跑团平台，不会自动判断玩家正在说什么，也不会直接替主持人向玩家发言。

## 最简单的启动方式

Windows 可以直接双击项目根目录中的：

```text
start_lorecue.cmd
```

也可以运行 Python 版本：

```text
start_lorecue.py
```

两个入口都会寻找可用的 Node.js 与 pnpm、启动样机，并打开
`http://localhost:3000/`。保持启动窗口开启即可继续体验；按 `Ctrl+C`
会停止完整的本地服务进程树并释放 3000 端口。

## 手动启动

需要 Node.js 22.13 或更高版本。

```bash
pnpm install
pnpm dev
```

验证构建与关键页面内容：

```bash
pnpm test
pnpm exec eslint app tests
```
